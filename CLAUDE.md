# Janngude — espace de révision pour étudiants

Application web (Next.js 16 + Supabase + Claude + ElevenLabs). Interface en **français**, identifiants de code en anglais.

## Stack et règles Next.js 16

- **Cache Components activé** : toute lecture dynamique (`cookies()`, `params`, `searchParams`, base de données) se fait dans un composant enfant enveloppé par `<Suspense>`. Les pages sont des coquilles statiques.
- `usePathname()` / `useSearchParams()` côté client ⇒ envelopper dans `<Suspense>`.
- Pas de `export const runtime`. `proxy.ts` remplace `middleware.ts`.
- Types globaux `PageProps<"/route">`, `LayoutProps<"/route">`, `RouteContext<"/api/…">` (générés par `npx next typegen`).
- Route handlers : toujours passer par `handleApiError` (relance les erreurs internes `NEXT_*`) ; les `GET` appellent `await connection()` pour sortir du prerender.
- Règles React Compiler (lint) : pas de `setState` synchrone dans un `useEffect` ; pas de `Date.now()` / `Math.random()` pendant le rendu.

## Serveur MCP Supabase

`.mcp.json` déclare le serveur MCP hébergé de Supabase (`supabase`), limité au projet `mduajsgfisucshvqknmr`
(URL `https://mcp.supabase.com/mcp?project_ref=…`). Authentification OAuth : `claude /mcp` dans un terminal,
puis « supabase » → « Authenticate ». Une fois connecté, il permet d’appliquer les migrations SQL, de lire les tables,
les journaux et la configuration Auth directement depuis Claude Code. Ajouter `&read_only=true` à l’URL pour un
usage en lecture seule ; garder la confirmation manuelle des appels d’outils.

## Données

- Schéma dans `supabase/migrations/0001_init.sql` puis migrations numérotées suivantes, toutes idempotentes (RLS : chaque étudiant ne voit que ses lignes). Voix personnalisées : table `voices` (plusieurs par étudiant, plafond `MAX_VOICES_PER_USER`), routes `/api/voices` ; les colonnes `profiles.voice_id/voice_name` sont héritées et ne sont plus utilisées. Types manuels dans `src/lib/supabase/types.ts` — **à tenir synchronisés** avec le SQL.
- Partages publics via les fonctions SQL `get_share`, `grade_shared_quiz`, `save_share`, `list_received_shares` (SECURITY DEFINER). Types partageables : résumé, quiz, audio, discussion et **cours complet** (`copy_shared_course` copie le cours dans l’espace du lecteur). Bucket `audio` public (chemins aléatoires), `courses` et `voices` privés.
- Migration `0004_features.sql` : cartes mémoire (`flashcards`, SM-2 dans `src/lib/srs.ts`), examens blancs (`exams`), **groupes de classe** (`groups`, `group_members`, code d’invitation, `join_group`, `group_members_list`, `group_shares_list`, `group_leaderboard` ; `shares.group_id`), recherche plein texte (`courses.search`, `search_courses`), suivi d’usage (`usage_events`, `logUsage()` dans `src/lib/usage.ts`), rôles (`profiles.role`, `is_admin()`, `admin_overview`, `admin_users`, `admin_set_role`) et accueil (`profiles.onboarded_at`).
- Partage à un groupe : option « Partager à un groupe de classe » dans `ShareDialog` (tous types) et bouton « Partager un contenu » sur la page du groupe (`ShareToGroupDialog`, bibliothèque via `GET /api/library`, un `POST /api/shares` avec `groupId` par contenu coché). Migration `0006_shared_chat.sql` : `courses.copied_from` / `chats.copied_from` (copies sans doublon) et `continue_shared_chat(token)` (route `/api/shares/[token]/continue`) qui copie le cours si besoin et la discussion avec ses messages dans l’espace du lecteur, puis redirige vers `/app/courses/{id}?tab=chat&chat={chatId}` (`initialChatId` dans `ChatPanel`) pour poser ses propres questions à l’assistant.
- Migration `0005_phone_search.sql` : `profiles.phone` (normalisé `+221…` par `src/lib/phone.ts`, saisi à l’inscription via `user_metadata.phone` et dans Paramètres) et `search_students(q)` (nom, e-mail ou téléphone, 2 caractères minimum, soi-même exclu) utilisée par l’autocomplétion du partage (`StudentPicker`, route `/api/students/search`).
- Espace admin `/admin` (`requireAdmin()`), suppression de comptes via `SUPABASE_SECRET_KEY`, état du quota ElevenLabs (`elevenSubscription()`). Premier admin : `update profiles set role='admin'` en SQL.
- ElevenLabs renvoie **401 `quota_exceeded`** quand les crédits du mois sont épuisés : `elevenFetch` distingue ce cas d’une clé invalide.
- Pas d’accueil ni de cours de démonstration (retirés à la demande du client) ; la colonne `profiles.onboarded_at` de la migration 0004 subsiste mais n’est plus utilisée.
- Imports (`src/lib/extract.ts`) : PDF (unpdf, transcription Claude si scanné), Word (mammoth), PowerPoint (jszip, `## Diapositive N` + notes), images (Claude), audio (ElevenLabs Scribe `scribe_v1`, `transcribeAudio` dans `src/lib/tts.ts`). Dépôt multiple : un cours par fichier, analyses lancées en `fetch(..., { keepalive: true })`. YouTube : `/api/courses/import-youtube` (`youtube-transcript`, paragraphes horodatés, titre via oEmbed). Note audio : enregistrement micro (`src/lib/use-recorder.ts`).
- E-mails d’authentification : si `SUPABASE_SECRET_KEY` et `RESEND_API_KEY` sont définies, `/api/auth/signup`, `/api/auth/forgot` et `/api/auth/resend-confirmation` génèrent les liens via `auth.admin.generateLink` et envoient via Resend (`src/lib/auth-mail.ts`) ; sinon les formulaires retombent sur l’envoi Supabase (503). Les liens aboutissent sur `/auth/confirm` (token_hash).
- Session : `getCurrentUser()` / `requireUser()` (`src/lib/auth.ts`) côté serveur ; `requireApiUser()` dans les routes API.

## IA

- Modèle : `CLAUDE_MODEL` (défaut `claude-opus-5-5`). Sorties structurées via `zodOutputFormat` (analyse, quiz) ; streaming NDJSON pour résumés et chat (`ndjsonResponse` / `readNdjson`).
- Prompts centralisés dans `src/lib/ai/prompts.ts`.
- Clé ElevenLabs : `NEXT_ILEVENLABS_KEY` (sans `PUBLIC`, côté serveur uniquement). Modèle `ELEVENLABS_MODEL` (défaut `eleven_v4`, expressif : balises `[short pause]`, `[exhales]`…, pas de SSML `<break>`). Voix par défaut `ELEVENLABS_DEFAULT_VOICE_ID`.
- Lecteur audio immersif (`src/components/audio/audio-player.tsx`) : sous-titres karaoké, texte complet synchronisé, sommaire cliquable et recherche avec autocomplétion. **Mode Parcœuriser** (apprentissage par cœur, bouton 🎓, mémorisé dans localStorage `janngude:learn-mode`) : la partie courante tourne en boucle (bornes = débuts de sections de la transcription) jusqu'à « Je maîtrise cette partie » (touche M), puis saut à la prochaine partie non maîtrisée ; parties validées par lecture dans `janngude:mastery:<id>` (`readMastery`/`saveMastery`, `src/lib/offline.ts`). En-tête du lecteur collé en haut (`sticky`, bouton « Retour » et croix toujours visibles) ; le suivi du texte fait défiler uniquement le panneau de transcription (`container.scrollTo`, jamais `scrollIntoView` qui déplaçait toute la fenêtre) et se suspend dès que l’étudiant fait défiler le panneau à la main (molette ou doigt ; « Suivre la lecture » le réactive). Il lit la transcription JSON (`src/lib/transcript.ts`, mots horodatés via l’endpoint ElevenLabs `with-timestamps`) stockée à côté du MP3 (`<fichier>.json`, bucket `audio`). La narration (`narrateForSpeech`) renvoie des sections structurées qui servent de sommaire.
- Podcast à deux voix : dialogue écrit par Claude (`src/lib/ai/podcast.ts`, `writePodcast`) à partir du cours complet (entrée plafonnée à 250 000 caractères) ; sa longueur est bornée par `podcastBudget` (`src/lib/podcast-budget.ts`, cible ≈ 1,2 × le cours, plafond 15 000 caractères soit 75 % de `TTS_MAX_CHARS`, filet `fitPodcast` à 18 750) : un cours long est condensé, jamais refusé. La limite `TTS_MAX_CHARS` (20 000) ne s’applique qu’aux autres sources ; l’onglet Écoute affiche la durée estimée du dialogue.
- Extrait d’une voix : `GET /api/voices/[id]/preview` (`default` pour la voix par défaut) renvoie un MP3 : l’aperçu ElevenLabs de la voix (`GET /v1/voices/{id}` → `preview_url`) ou, à défaut, `VOICE_PREVIEW_TEXT` synthétisé (`voicePreview` dans `src/lib/tts.ts`, usage `tts_chars`) ; mis en cache dans le bucket `voices` (`<user>/previews/<id>.mp3`). Bouton « Écouter » (`VoicePreviewButton`, un seul extrait à la fois) sur les cartes de voix des Paramètres et à côté du choix de voix de l’onglet Écoute.
- Lecture audio (`src/lib/tts.ts`) : PCM 24 kHz demandé par morceaux de 3 000 caractères avec `previous_text`/`next_text`, normalisation du niveau (`src/lib/audio.ts`, cible −15 dBFS, limiteur doux) puis encodage MP3 pur JS. Mode « narration naturelle » : le texte est d’abord réécrit en script oral par Claude (`src/lib/ai/narrate.ts`, prompt `SYSTEM_NARRATE`) ; mode « lecture fidèle » : `markdownToSpeech` avec pauses aux titres.

## Design (maquette « tablette » pastel)

- Page cyan clair (`page`), **cadre noir arrondi** (`DarkFrame`, `src/components/shell/app-shell.tsx`) avec barre de navigation sombre, puis **panneau clair** (`paper`) très arrondi. Encoche décorative noire en haut au centre.
- **Responsive** : sous `md`, `TopNav` est masquée et `MobileNav` (barre flottante blanche en bas, 5 entrées dont « + » noir) prend le relais via le slot `bottom` de `DarkFrame` (padding bas `pb-32`) ; `TabsDock` remonte au-dessus (`bottom-[calc(5.25rem+safe-area)]`). Les autres entrées (Examens, Recherche, Paramètres, Installer l’application) sont dans `UserMenu`. Vérification visuelle : pages de prévisualisation temporaires + captures CDP à 390/820 px (script `cdp-shots.mjs` dans le scratchpad de session).
- **Installation (PWA)** : `src/lib/install.ts` capture `beforeinstallprompt` (appelé par `PwaRegister`) ; `InstallAppButton` (`src/components/pwa/install-button.tsx`) déclenche l’invite native ou affiche les instructions iOS / Android / ordinateur ; présent sur l’accueil, dans Paramètres (carte « Application », ancre `#application`) et dans le menu du compte. Manifeste avec `id`, icônes 192/512 + maskable, service worker à gestionnaire `fetch` (requis par Chrome). En mode installé (`display-mode: standalone`), la variante Tailwind `standalone:` déclarée dans `globals.css` fige l’en-tête de `DarkFrame` en haut de l’écran (`sticky`, fond `ink`, cadre en `overflow-clip`) ; dans un onglet classique, l’en-tête défile normalement.
- Tokens dans `src/app/globals.css` : `ink` (noir, actions principales), pastels `mint`, `sky`, `lavender`, `lemon`, `pink`, `violet`. Police unique **Rubik** (`font-sans`) ; titres en `font-semibold tracking-tight` avec un emoji (`&nbsp;` avant l’emoji).
- Formes : cartes `rounded-[28px] bg-surface shadow-card` sans bordure, boutons et champs en pilule (`rounded-full`), pastilles de statut pastel (« Prêt 👏 »), pastille icône en coin de carte (`CornerBubble`).
- Page cours : onglets dans la **barre d’outils flottante** noire (`TabsDock` / `TabsDockTrigger`, un pastel par onglet). Onglet Écoute (`audio-panel.tsx`) : sources en **cartes radio** (icône pastel + durée estimée, carte active noire, podcast sur deux colonnes), réglages en lignes `SettingRow` (icône, libellé, aide, `Segmented` à droite, empilées sous `md`), barre de lancement noire avec l’estimation et le bouton blanc « Générer le MP3 ». Tableau de bord : tuiles Total / Prêts / En analyse, grille à plat filtrée par formation puis matière, colonne « Partagés avec moi » en cartes pastel (`SharedCard`).
- Composants UI maison dans `src/components/ui` (Radix pour dialog, tabs, dropdown, tooltip). `cn()` dans `@/lib/utils`.
- **Mascotte Khadija** (`src/components/brand/khadija.tsx`) : l’assistante de l’application. Illustrations fournies par le client dans `public/khadija/<pose>.png` (360 × 360, fond transparent, nettoyées depuis la planche d’autocollants : fragments retirés, recadrage carré, personnage calé en bas). 30 poses : `hello` (salut), `thumbsup`, `cheer`, `love`, `think` (point d’interrogation), `idea` (ampoule), `laptop`, `study` (écrit, livres), `books` (présente des livres), `phone`, `point` (montre du doigt), `confident` (bras croisés), `surprise`, `ok`, `tablet`, `zen` (méditation), `headphones` (casque), `microphone`, `upload` (dossier de documents), `flashcards` (cartes), `graduate` (diplôme), `trophy`, `oops` (désolée), `encourage` (poing serré), `search` (loupe), `friends` (deux amies), `timer` (chronomètre), `offline` (téléphone sans réseau), `admin` (presse-papiers de statistiques), `install` (téléphone avec l’application). Nouvelles poses : images fournies par le client, nettoyées par le même script (scratchpad `imgtools/clean.mjs`). `Khadija` (`pose`, pastille pastel `bg` qui recadre le buste en rond, `next/image`), `KhadijaFigure` (Khadija en grand avec une bulle : `row` à côté d’elle, `column` au-dessus d’elle avec une pointe, `auto` = row sur téléphone puis column ; jamais en pastille, le client préfère les illustrations entières), `EmptyState mascot={{ pose }}`. Attribution cohérente : discussion (avatar `confident`, accueil `idea`), accueil public (bulle `laptop`), authentification (`hello`), bibliothèque vide (`books`), dépôt de cours (`upload`), révisions du jour et cartes mémoire vides (`flashcards`), analyse en cours (`study`), échec d’analyse et page d’erreur `src/app/error.tsx` (`oops`), rien à réviser (`zen`), examens vides (`graduate`), formulaire d’examen (`timer`), bilan d’examen (`graduate` ≥ 70 %, sinon `encourage`), recherche (`search`, aucun résultat `think`), partages reçus vides (`love`), groupes vides (`friends`), classement du groupe (`trophy`), voix personnalisées (`microphone`), onglet Écoute et page hors ligne (`headphones`, bandeau hors connexion `offline` ; les deux précachés par le service worker), quiz (`trophy` ≥ 70 %, `thumbsup` ≥ 40 %, sinon `encourage`), administration (`admin`), installation (`install`, dialogue et Paramètres), 404 (`surprise`). Présence transversale : icônes des notifications `sonner` (`ok` succès, `oops` erreur, `idea` info, `surprise` avertissement, dans `src/app/layout.tsx`), mot d’accueil contextuel du tableau de bord (`study` pendant une analyse, `ok` quand tout est à jour ; absent si des cartes sont dues ou sans cours), accueil public (étapes `upload` / `study` / `headphones`, section partage `friends`), en-têtes « Nouveau quiz » (`tablet`) et « Cartes mémoire » (`flashcards`), progression de la génération audio (`study` → `microphone` → `headphones`), dialogue de partage (`friends`), page de partage public (`point`), session de révision (`flashcards` dans l’en-tête ; bulle `think` côté question, `idea` côté réponse, `encourage` après « Encore », `thumbsup` après « Facile »), fin de session (`cheer`, `thumbsup` s’il reste des cartes à retravailler), code d’invitation d’un groupe (`phone`), vignette du lecteur audio immersif (`headphones` en lecture, `ok` en pause, `study` en mode Parcœuriser, `cheer` quand toutes les parties sont maîtrisées). L’IA se présente comme Khadija (`ASSISTANT_IDENTITY` dans `src/lib/ai/prompts.ts`).
